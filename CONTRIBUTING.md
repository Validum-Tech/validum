# Как участвовать в разработке

Спасибо, что заглянули. Ниже — минимум, который нужен, чтобы ваш PR приняли быстро.

## Прежде чем писать код

1. **Откройте issue.** Опишите задачу или баг: версия, команда, ожидаемое и фактическое поведение.
   Это экономит время: возможно, решение уже есть или задача сознательно отложена.
2. **Соберите проект** (JDK 21):

   ```bash
   ./gradlew build          # компиляция + тесты + jacoco
   java -jar validum-cli/build/libs/validum.jar version
   ```

3. **Для API/CLI нужен справочник БИК** — без него будет 503 `bik_source_missing`:

   ```bash
   java -jar validum-cli/build/libs/validum.jar fetch-bik -o data/ED807.xml
   ```

## Правила кода

- **`validum-core` без runtime-зависимостей.** Это принцип, а не случайность: новая библиотека
  в core принимается только с обоснованием в issue.
- **Никаких LLM в продукте.** Только детерминированные алгоритмы: один `seed` (+ `asOf`) —
  один и тот же профиль вчера, сегодня и через год.
- **Идентификаторы — английские, документация и UI — русские.**
- **Форматирование**: 2 пробела в Java, `.editorconfig` включён в репозиторий.
- **Окончания строк**: LF; Windows-скрипты (`*.ps1`, `*.bat`) — CRLF. Настроено в `.gitattributes`.

## Тесты

- Новое поведение — с тестом (JUnit 5 + AssertJ). Названия `@DisplayName` — по-русски.
- Покрытие не должно падать. Текущее: core ~91%, api ~92%, cli ~66% (jacoco, `./gradlew build`).
- Прогон только одного класса: `./gradlew :validum-core:test --tests "ru.validum.core.bank.*"`.

## Что проверить перед PR

```bash
./gradlew build                     # тесты + покрытие
git diff --check                    # пробелы, конфликтные маркеры
java -jar validum-cli/build/libs/validum.jar version
```

Чек-лист PR:

- [ ] тесты зелёные, покрытие не упало;
- [ ] обновлены `README.md` / `CHANGELOG.md`, если изменилось поведение или цифры;
- [ ] нет секретов, локальных путей и отладочного вывода (`System.out`, `printStackTrace`);
- [ ] коммит-сообщения описывают то, что реально в диффе (одна мысль — один коммит).

## Стиль коммитов

```
тип(область): что сделано

почему это нужно, если неочевидно
```

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `perf`. Пример:
`fix(account): ключ счёта считается от БИК банка`.
