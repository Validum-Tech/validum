# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [Unreleased] — 0.5.0

Ничего не запланировано — состав следующей версии определится после 0.4.0.

## [0.4.1] — 2026-11-14

Патч: REST-сервис больше не принимает `?fields=` молча для JSON-форматов.

### Fixed
- `POST /api/v1/generate/{individual,ip,organization}/batch?fields=…&format=json|json-array`
  теперь отвечает `400 {"error":"invalid_argument"}` с подсказкой про `format=csv`; раньше параметр
  игнорировался и клиент получал полный набор, не зная об этом.
- `tools/rest-smoke.py` читает БИК из вложенного `bank.bik` (раньше `validate/account` падал с пустым
  БИК), смоук REST в CI берёт boot-jar, а не `-plain.jar`, `tools/consumer-smoke.py` вызывает
  `BikSources.resolve(String)`.

## [0.4.0] — 2026-11-14

Планируется: `--format xlsx` без зависимостей, разложение `core/export` по слоям,
`@Mixin`-опции CLI, README → `docs/*`.
Полный список — [`docs/ROADMAP-0.4.0.md`](docs/ROADMAP-0.4.0.md).

Версия также закрывает дефекты 0.3.0, которые не выпускались отдельным хотфиксом.

### Added
- **Предрелизная проверка `tools/release-check.py`** (+ `release-check.ps1`): сверяет версии
  (`gradle.properties`, витрина, CHANGELOG, координаты в `docs/*`), содержимое fat jar
  (размер, `java -jar … version`), поверхность (`--help` девяти команд, 16 опций `generate`,
  19 REST-эндпоинтов), количество исполнений в отчётах тестов, ссылки README и полноту
  `tools/whitelist.py`; поведением проверяет генерацию, детерминизм по seed, `validate inn`
  и `coverage`. В CI — шаг `release-check` после сборки jar, плюс `demo-check`. Код возврата
  1 останавливает релиз.
- **Регион адреса в плоской выдаче:** `registrationRegion`, `registrationRegionType`, `postRegion`,
  `postRegionType`, `currentRegion`, `currentRegionType` — аддитивно. Раньше в CSV был город,
  улица и индекс, но не субъект, и адрес нельзя было сверить с анкетой или ЕСИА.
- **Читаемый эталон в golden:** рядом с `individual.txt`/`organization.txt` появились
  `*-preview.txt` (поле=значение, seed 0), чтобы изменение контракта было видно в диффе, а не
  только «хеш другой».
- **Колонка `passportExpirationDate` («Действителен до»)** в плоской выдаче CLI и в
  `describe`: срок паспорта РФ теперь виден в CSV, а `fill` читает его обратно, поэтому
  дозаполнение не теряет поле. Изменение аддитивное — для тех, кто читает по именам колонок,
  ничего не ломается.

### Fixed
- Адреса: почтовый индекс теперь реальный (из `DOMA.DBF`), а не случайные шесть цифр.
  В выгрузке КЛАДР колонка `INDEX` пустая, поэтому срез собирался без индексов и
  «Самарская обл» могла получить индекс Псковской области. Индекс населённого пункта
  приходит из домов КЛАДР; аварийный путь (если индекса нет) остаётся в границах
  своего субъекта — карта префиксов `addresses/index-prefixes.tsv`.

- **`-o out\sub\file.json` падал с `NoSuchFileException`**: каталог назначения создаётся
  сам (`OutputFiles`), это работает для всех команд с `-o`.
- **`--age-distribution realistic` без `--age-range` игнорировался**: весь набор был из
  19-летних. Теперь распределение работает и без диапазона (когорты 0–110).
- **`generate --spec` со `"ageRange"`, но без `"ageDistribution"` падал с
  `NullPointerException`** в `parseAgeDistribution` — теперь по умолчанию `uniform`.
- **`--unique-pool` был декоративным**: пул не ограничивал перебор. Теперь исчерпание
  наступает ровно после N значений, текст — «пул исчерпан: выдано N из N вариантов».
- **Паспорт РФ: срок действия по возрастным рубежам.** Раньше у 25-летнего паспорт был
  «бессрочным», а у 66-летнего дата выдачи могла оказаться в 30 лет. Теперь паспорт,
  выданный до 20 лет, действует до 20-летия, до 45 — до 45-летия, после 45 — бессрочно,
  а дата выдачи не раньше последнего пройденного рубежа (14/20/45).
- **Паспорт РФ больше не дублируется** в «Дополнительных документах» при `--documents auto`.
- **`fill` с несуществующим входным файлом** печатает «файл не найден — <путь>» вместо
  стектрейса.

## [0.3.0] — 2026-11-13

Пакет «данные как в реале»: человек с историей и документами по возрасту, нерезиденты,
чтение спецификации набора, поиск и проверка готовых данных, намеренно испорченные строки.

### Added

- **Диапазон возраста `--age-range MIN-MAX` и `--age-distribution uniform|realistic`.**
  Раньше `--age` задавал одно число на весь прогон, поэтому тысяча профилей была тысячей
  19-летних. Теперь каждый профиль берёт свой возраст из диапазона: `uniform` — равномерно
  (края распределения тоже встречаются), `realistic` — по демографическим когортам
  (трудоспособных больше, детей и пенсионеров меньше). Без диапазона поведение прежнее:
  `--age` или каскадный дефолт 19. В спецификации набора появились поля `ageRange` и
  `ageDistribution`; в CLI команды `ip` диапазон тоже поддержан.
- **`--documents auto` — набор ДУЛ по возрасту и полу.** Раньше документы перечислялись
  руками, и легко было получить права у семнадцатилетнего. Теперь `auto` подбирает набор
  по жизненным вехам: до 14 лет — ничего, с 14 — паспорт РФ, с 18 — права, мужчинам
  призывного возраста — военный билет; нерезиденту — паспорт иностранца и, с 18 лет, ВНЖ.
  Набор строится методом `DocumentRules.autoSelect` и гарантированно проходит
  `DocumentRules.validate` (проверено на 1000 профилях).
- **Нерезиденты: `--residency` и `--country`.** Все три адреса профиля генерируются в стране
  проживания (Алматы, Минск, Берлин, Нью-Йорк и ещё семь стран), набор ДУЛ собирается под
  нерезидента (паспорт иностранного гражданина, ВНЖ с 18 лет), в плоской выдаче появились
  колонки `isResident` и `citizenship`. Типовые улицы — синтетические, не из реестра.
- **`--index` и `describe` — найти человека в наборе.** `generate individual --index` печатает в
  stderr таблицу «№ · идентификатор · ФИО · возраст · регион · банк · счёт», а
  `validum describe --file <набор> --person <идентификатор>` (или `--row 3`) показывает карточку
  человека: документы, адреса, банк, флаги и результат проверок — ИНН, СНИЛС, счёт и
  согласованность. CSV с русскими заголовками и JSON читаются одинаково.
- **`--corrupt` — намеренная порча для негативных тестов.** `--corrupt inn,snils,address`
  ломает контрольную сумму ИНН, контрольное число СНИЛС или формат адреса (пустой индекс и строка
  «ул. , д. , кв. »), а в stderr пишет `# испорчено: inn,address` — чтобы битую строку нельзя было
  спутать с багом генератора. То же работает из спецификации: `"corrupt": ["inn"]`.
- **`coverage` проверяет согласованность и показывает распределения.** Кроме заполненности и
  контрольных сумм отчёт отвечает на вопрос «набор не врёт сам себе»: возраст против
  минимального возраста документа, нерезидент против паспорта РФ, серия паспорта против органа,
  выдавшего его, счёт без банка. Нарушения печатаются с номером строки и правилом, ниже —
  распределения по полу, резидентству, региону, банку и семейному положению и сводка возраста
  (мин/средний/макс).
- **`personId` — детерминированный идентификатор человека** (в разделе «Изменено» ниже).

### Added
- `--fields` для `generate individual|ip|organization`: оставить только нужные колонки
  (пресет `short` — «человеческий» набор). В спецификации — `"fields"`, в REST — `?fields=`
  для CSV-батчей; неизвестная колонка даёт ошибку со списком доступных, а не пустой столбец.
  `?fields=` вместе с `format=json|json-array` отбивается `400 invalid_argument` — для JSON набор
  уже структурирован, и молча игнорировать параметр нельзя.

### Changed
- **README разложен по `docs/*`:** лендинг на 71 строку (что это, 30 секунд, таблица разделов,
  цифры, лицензия), а подробности — `docs/QUICKSTART.md`, `docs/FEATURES.md`, `docs/CLI.md`,
  `docs/REST.md`, `docs/INTEGRATIONS.md`, `docs/PROJECT.md`. Ни один раздел из старого README
  (1165 строк) не потерян: перенесён дословно, внутренние ссылки поправлены.
- **`IndividualProfileGenerator.Builder` вынесен** в самостоятельный `IndividualProfileBuilder`
  (тот же пакет `ru.validum.core.profile`). `IndividualProfileGenerator.builder()` по-прежнему
  возвращает билдер, набор сеттеров не изменился — для потребителя это только новый импорт при
  явном объявлении типа переменной.
- **Общие опции CLI — один mixin:** `--seed`, `-n/--count`, `--format`, `--dialect`, `--table`,
  `--no-ddl`, `-o/--output` вынесены в `CommonOptions` (`@Mixin`). Поведение и значения по
  умолчанию не изменились; `--table` по-прежнему подставляет имя таблицы своей сущности.


- `managers.txt` — одна заглушка «Менеджер клиента» вместо 50 строк `ААА/ВВВ/…`: поле
  `personalManager` больше не выглядит как сырой тестовый набор. Явное `personalManager("…")`
  в билдере по-прежнему переопределяет значение.


- `coverage`: отчёт больше не читается как проверка контрольных сумм — перед правилами
  печатается строка «Валидность значений: проверено N полей, невалидных M из K значений»,
  а блок правил назван «Согласованность набора (правила: документ/возраст, серия/регион
  выдачи, счёт/банк)».

- **Порог Java 17 для CLI и библиотек.** `validum-core`, `validum-allure` и `validum-cli`
  компилируются с `options.release = 17` (байткод major 61), сборка идёт на toolchain 21.
  REST-сервис `validum-api` остаётся на 21 — его требует Spring Boot 3.5.
  В CI добавлена полоса проверки на JDK 17 (`-Pvalidum.javaToolchain=17`), чтобы «договор про 17»
  проверялся сборкой, а не обещанием в README.
- **`personId` — детерминированный идентификатор человека.** Выводится из seed (`pd-` + 16 hex
  sha-256), в батче seed профиля равен базовому плюс индекс, поэтому один и тот же человек
  получает один и тот же `personId` в CLI, REST и CSV. Поле аддитивное: появилось в JSON,
  DTO и первой колонкой плоского вывода (`Идентификатор` в русском CSV), в импорте CSV читается
  обратно. Golden-фикстуры `personId` не включают — он производный от seed и проверяется
  отдельными тестами (`PersonIdsTest`, `PersonIdOutputTest`, `PersonIdApiTest`).
- **`validum-allure` больше не навязывает версию Allure.** Зависимость `allure-jupiter` убрана:
  модуль компилируется против `allure-java-commons:2.29.1`, и в опубликованный POM она не попадает
  (`compileOnly`). Потребитель приносит свою версию Allure — 2.29.x (`allure-junit5`) или 2.35.x
  (`allure-jupiter`). Мы прогоняем свои тесты на полу 2.29.1, а тест `AllureDependencyFloorTest`
  падает, если main-код снова начнёт ссылаться на `allure-junit5`/`specs`/`model`.
- **Даты документов привязаны к дате рождения.** У вида документа появились возрастные окна
  (`minAge`/`maxAge`): паспорт РФ — с 14 лет, права и военный билет — с 18, военный билет рядового
  состава — до 27. Дата выдачи теперь не раньше «дата рождения + minAge», а у документов со сроком
  действия — ещё и не раньше «дата расчёта − срок», чтобы на дату расчёта он не был просрочен.
  Правила `DocumentRules` читают окна из перечисления, поэтому проверка возраста и генерация
  больше не расходятся.
- **Сборка и тесты — одна конфигурация.** Toolchain, `options.release`, UTF-8, `-Xlint:all`,
  JUnit Platform и `validum.bik.file` заданы один раз в корневом `build.gradle.kts`
  (`subprojects`); из четырёх модульных скриптов копии убраны.
- **Один разбор CSV.** `CsvImporter` умеет работать с разделителем (`','`, `';'`), определяет его
  по заголовку и снимает Excel-обёртку `="…"`; `DatasetReader` в CLI больше не держит собственный
  построчный парсер. Побочный эффект — `describe` и `coverage` корректно читают CSV со значениями
  в кавычках и переносами строк внутри.
- **Тестовый каркас.** `TestProfiles` (seed + справочник БИК + дата расчёта в одном месте) и
  `golden/README.md` с порядком обновления эталонов.

### Fixed

- **`csv-semicolon` больше не портится в Excel.** Кодовые колонки (ИНН, СНИЛС, счёт, корсчёт,
  БИК, КПП, ОГРН/ОГРНИП, ОКПО, индексы, серия и номер паспорта, телефон) пишутся текстом
  (`="586272979740"`): Excel больше не превращает их в `5,86E+11`, не обрезает 20-значные счета
  и не съедает ведущий ноль у индекса `053796`. Машинный `csv` не изменился.
- **«Кем выдан» согласован с регионом прописки.** Паспорт РФ и военный билет выдаются органом
  региона регистрации: у человека из Московской области больше нет паспорта, выданного в
  Екатеринбурге, а военкомат совпадает с регионом призыва. Код подразделения начинается с кода
  того же региона. Без явного `--region` регион выбирается один раз на человека и используется
  и паспортом, и адресами. Падежи для всех 16 регионов — в `Region#department()`.
- **`describe` и `coverage` читали не те колонки.** Русские заголовки паспорта и документов
  совпадали («Кем выдан», «Дата выдачи», «Код подразделения»), из-за чего эти поля не находились
  и печатались пустыми; заголовки документов получили суффикс «(документ)», а `coverage` на
  «дружелюбном» CSV вообще не проверял ключевые поля — теперь переводит заголовки в ключи.
- **Адрес печатается по-человечески.** Вместо `624672,Свердловская обл,,,Катышка д,,1 Мая ул,31,225`
  — `624672, Свердловская обл., г. Катышка, ул. 1 Мая, д. 31, кв. 225`: пустые части не клеятся,
  тип поселения и улицы стоит перед названием.

## [0.2.0] — 2026-11-03

Пакет «Набор»: данные воспроизводимы, уникальны и читаемы человеком без шаманства.

### Added

- **Версия и seed в выводе.** CLI пишет в stderr строку `# validum <версия> · seed=N · asOf=YYYY-MM-DD`
  и подсказку с готовой командой `--seed`, если seed сгенерирован автоматически. REST отдаёт заголовки
  `X-Validum-Version` и `X-Validum-Seed`; SQL-скрипт начинается с `-- validum <версия>, seed=N`.
  Версия берётся из одного места — `ru.validum.core.Version` (системное свойство `validum.version`
  из Gradle → манифест jar → `dev`), а не хардкод. Заголовки отдают все генеративные эндпоинты,
  включая батчи и CSV.
- **Уникальность с проверкой ёмкости** (`--unique` в `generate individual|ip|organization`).
  Дубликаты ИНН (ФЛ), ОГРНИП (ИП) и ОГРН (ЮЛ) не выпускаются: при совпадении профиль
  перегенерируется с новым seed. В режиме `--unique` seed обязателен — иначе набор невоспроизводим.
  При исчерпании вариантов — ошибка «не удалось получить уникальный ИНН за 1000 попыток
  из M вариантов», без бесконечного цикла.
- **`csv-semicolon` — CSV для русского Excel**: UTF-8 с BOM, разделитель «;» и русские заголовки
  («ФИО;ИНН;СНИЛС…»). CLI `--format csv-semicolon`, REST `?format=csv-semicolon`. Машинный `csv`
  не изменился: «,» и английские заголовки.
- **Спецификация набора `.validum.json` (C1)**: `validum generate --spec set.validum.json` —
  `type` (или русский синоним `фл`/`ип`/`юл`), `count`, `seed`, `asOf`, `format`, `output`, `unique`,
  `options{region, age, gender, bik, okved, documentTypes…}`. Исполняется тем же кодом, что и флаги;
  неизвестный ключ отклоняется с кодом 2, при `unique` без `seed` — отказ.
- **Регрессионная сетка (N1)**: `PropertyInvariantsTest` сверяет валидаторы с независимой
  реализацией алгоритмов (ИНН, СНИЛС, ОГРН/ОГРНИП, контрольный ключ счёта по письму № 515) на
  случайных данных и проверяет свойства сгенерированных профилей; `GoldenFixturesTest` фиксирует
  SHA-256 набора для пары `seed + asOf` — дрейф справочников или порядка колонок ловится сразу.
  Обновление эталона — `./gradlew :validum-core:test -Dvalidum.golden.update=true`.

## [0.1.0] — 2026-10-30

Первая публичная версия: генерация валидных данных для российского финтеха, self-hosted, без LLM.

### Added

**Данные**
- ФЛ: ФИО (по полу и региону), дата рождения и возраст, ИНН, СНИЛС, паспорт РФ / иностранный,
  адреса (регистрации, проживания, фактический), контакты, секретное слово, категория клиента,
  пакет услуг, персональный менеджер, признаки «террорист»/«заблокирован».
- ИП: профиль ФЛ + ОГРНИП, ОКВЭД-2 с наименованием.
- ЮЛ: 7 организационно-правовых форм, ОГРН, ИНН, КПП (по региону), ОКПО, банк по БИК и расчётный
  счёт 40702 (ключ по письму ЦБ № 515), ОКВЭД-2 с наименованием.
- Счета: 12 типов из классификатора ЦБ (`AccountType`), контрольный ключ по письму ЦБ № 515
  (условный номер подразделения, буквенные коды валют), проверка `isValid` / `isValidAuto`.
- Документы (ДУЛ, СПДУЛ ФНС): 11 видов — паспорт РФ (21), дипломатический (09), загранпаспорт (22),
  паспорт иностранного гражданина (10), ВНЖ (12), РВП (15), удостоверение беженца (13), военный
  билет (07), военный билет офицера запаса (27), виза, водительское удостоверение. Правила
  совместимости — `DocumentRules` (загранпаспорт требует паспорт РФ; ВНЖ/РВП/беженец — только
  нерезидент; военный билет — мужчина 18–27).
- Адреса: реальный справочник КЛАДР — 90 субъектов, 125 413 населённых пунктов, 1 993 702 улицы;
  дом и квартира генерируются процедурно, индекс — из КЛАДР.
- Банки: полный справочник участников ЦБ РФ из ED807 — 1380 участников, 370 действующих банков,
  17 типов участников (`PtType`), фильтр по типу в CLI и REST.
- ОКВЭД-2: полный классификатор, 3069 позиций.

**Сценарии**
- 9 готовых КУС-сценариев (`ScenarioCatalog`): взрослый с/без счёта, пенсионер (М/Ж), зарплатный
  клиент, нерезидент с ВНЖ, иностранец с визой, военнослужащий, несовершеннолетний.

**Поверхности**
- REST API (Spring Boot 3.5, virtual threads): генерация ФЛ/ИП/ЮЛ одиночная и пакетная, дозаполнение
  CSV, сценарии, 8 валидаторов, экспорт ED807/ED808.
- CLI (picocli, fat jar): `generate` (individual / ip / organization / documents), `fill`, `validate`,
  `participants`, `scenarios`, `export` (ed807 / ed808), `fetch-bik`, `version`.
- Java-библиотека (`validum-core` без runtime-зависимостей) + JUnit 5 extension для Allure
  (`@ValidumSeed`, `@ValidumGenerate`).
- Форматы вывода: JSON (обёртка и массив), CSV (плоский, RFC 4180, UTF-8 BOM), SQL (DDL + INSERT для
  PostgreSQL / Oracle / MySQL), ED807/ED808 XML (windows-1251).

**Детерминизм**
- `seed` + явная дата расчёта `asOf` полностью определяют профиль; одинаковый набор данных вчера и
  сегодня. API — поле `"asOf"`, CLI — `--as-of`, builder — `.asOf(LocalDate)`.
- Дозаполнение CSV: непустые ячейки не трогаются, пустые заполняются, недостающие колонки добавляются.

**Инфраструктура**
- `Dockerfile` (multi-stage, JRE 21) и `docker-compose.yml` с монтированием справочника ЦБ.
- GitHub Actions: сборка, тесты, публикация артефактов и сводки по модулям.
- 721 тест (567 core + 80 api + 55 cli + 19 allure), 0 падений.
- **Отчёт о покрытии набора** — `coverage --file <csv|json>`. Показывает, во что превратился файл:
  сколько строк заполнено, сколько значений различных и проходят ли контрольные суммы ИНН, СНИЛС,
  ОГРН/ОГРНИП, КПП, ОКПО и ключ счёта (БИК берётся из той же строки набора). Понимает «дружелюбный»
  CSV (BOM + `;`), машинный CSV, JSON и JSON-массив — формат можно задать `--format`. Ядро отчёта —
  `ru.validum.core.report.Coverage`, оболочка — `ru.validum.cli.CoverageCommand`.
- **Публикация в Maven Central.** Релиз больше не уходит в GitHub Packages: `validum-core` и
  `validum-allure` публикуются через Central Portal (`com.vanniktech.maven.publish`, авторелиз).
  Шаг в `release.yml` включается только при заданных секретах — без них релиз собирается и
  выкладывается как обычно, но пакет в Central не отправляется. Координаты для потребителей:
  `io.github.validum-tech:validum-core:0.2.0` без подключения репозитория.

### Changed

- Регион принимается единым валидатором `@ValidRegion` (имя enum или код субъекта) — раньше одиночные
  эндпоинты ФЛ/ИП отбивали 11 регионов из 16.
- Источник БИК — один на всех (`BikSources`): явный файл → `VALIDUM_BIK_FILE` → `validum.bik.file` →
  `data/ED807.xml`. Встроенный демо-набор из 30 банков удалён: справочник обязателен, иначе
  `BikSourceNotFoundException` (CLI exit 2, REST 503).
- CSV профиля: колонка `documents` (три режима — `inline`, `json`, `split`) и колонка `asOf`.
- У ЮЛ появились банк и счёт; у ИП — ОКВЭД-2.

### Fixed

- Расчёт контрольного ключа счёта: вместо подстановки кода валюты — условный номер подразделения по
  письму ЦБ № 515 (все 1338 счетов справочника ЦБ проходят проверку).
- Возраст и даты документов больше не зависят от календарной даты запуска.
- Демо-режим больше не маскирует отсутствие справочника БИК.

### Security

- В продукте нет обращений к LLM и внешним сервисам во время генерации: только детерминированные
  алгоритмы и локальные справочники. Все данные синтетические, персональных данных не содержат
  (совпадение с реальными ФИО/ИНН теоретически возможно — данные предназначены для тестовых контуров).
