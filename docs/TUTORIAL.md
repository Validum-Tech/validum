## 0. Что вы получите

Validum генерирует **синтетические, но валидные** данные для российского финтеха: ИНН, СНИЛС,
ОГРН/ОГРНИП, КПП, ОКПО, БИК и корсчёт из справочника ЦБ, счёт по 809-П, паспорта, адреса из
КЛАДР, ОКВЭД-2. Контрольные суммы настоящие — их понимают те же валидаторы, что стоят у банка.

Три свойства, из-за которых инструмент вообще нужен:

1. **Валидность.** Данные проходят проверку, а не выглядят похожими.
2. **Воспроизводимость.** `--seed` + `--as-of` дают тот же набор на любой машине.
3. **Согласованность.** Серия паспорта, регион прописки, банк и счёт не противоречат друг другу.

Данные **синтетические**: боевые персональные данные использовать нельзя (152-ФЗ), и Validum
для этого не предназначен.

## 1. Установка

Нужен Java 17+ (столько же требует REST-сервис на Spring Boot 4). Скачайте `validum-<версия>.jar` из
[GitHub Releases](https://github.com/Validum-Tech/validum/releases) или соберите сами:

```bash
./gradlew :validum-cli:shadowJar        # → validum-cli/build/libs/validum.jar
```

Проверка, что всё на месте:

```powershell
java -jar validum.jar version
# validum 0.4.1
# Java: 21
```

> Дальше в примерах используется `java -jar validum.jar` — замените на свой путь к jar.

## 2. Справочник БИК

Банковские сценарии (банк, счёт, корсчёт) работают только со справочником участников ЦБ —
встроенного демо-набора в продукте нет, чтобы не было «двух правд».

```powershell
java -jar validum.jar fetch-bik -o data/ED807.xml
# Скачано: data/ED807.xml, <размер> байт
# Справочник: 1 360 участников, из них 368 действующих банков
```

Проверить, что справочник читается:

```powershell
java -jar validum.jar participants -f data/ED807.xml --type 20 -l 5
# таблица: БИК | PtType | Тип | Корсчёт | Наименование
```

Флаги: `-f` — путь к файлу (обязателен), `--type` — код типа участника (20 — действующие банки),
`-l` — сколько строк показать.

> Если файла нет, банковские сценарии честно падают: CLI — код `2`, REST — `503 bik_source_missing`.
> Это не баг, а защита от тихого отката на «непонятно что».

## 3. Первые профили и детерминизм

```powershell
java -jar validum.jar generate individual --seed 42 -n 3
```

Увидите в stderr строку меты и три профиля в JSON:

```
# validum 0.4.1 · seed=42 · asOf=2026-11-15
```

Мета печатается всегда — она и есть ответ на вопрос «какие данные вы сгенерили».
Повторите команду с тем же `--seed` — получите тот же набор:

```powershell
java -jar validum.jar generate individual --seed 42 -n 3 -o out/a.json
java -jar validum.jar generate individual --seed 42 -n 3 -o out/b.json
Get-FileHash out/a.json, out/b.json    # одинаковые SHA-256
```

Поменяйте `--as-of` — данные пересчитаются на другую дату (возраст, срок действия паспорта):

```powershell
java -jar validum.jar generate individual --seed 42 -n 3 --as-of 2030-01-01 --format json-array
```

Что важно знать сразу:

- `--seed` без `--as-of` — берётся сегодняшняя дата; прогон через месяц даст другой набор.
- Хотите «как было месяц назад» — задайте `--as-of` явно.

## 4. CSV, который открывается в Excel

Обычный CSV ломается в русском Excel: ИНН превращается в `5,86E+11`, счёт теряет точность,
индекс — ведущий ноль, дата — `#######`.

```powershell
java -jar validum.jar generate individual --seed 7 -n 3 --format csv-semicolon -o out/clients.csv
```

Отличия `csv-semicolon` от обычного `csv`:

- UTF-8 **с BOM** — Excel определяет кодировку сам;
- разделитель `;` — как в русской локали;
- русские заголовки («ФИО», «ИНН», «Счёт»);
- кодовые колонки пишутся текстом `="…"` — Excel не переформатирует ИНН, счёт, индекс и телефон.

Машинный `csv` (без BOM, с `,`) оставлен как есть — для скриптов и конвейеров, ему Excel не нужен.

## 5. Только нужные колонки

В полном профиле больше 60 колонок — для теста это лишнее. Есть явный список и пресет:

```powershell
java -jar validum.jar generate individual --seed 7 -n 3 --fields inn,fullName,account --format csv
# заголовок: fullName,inn,account  (порядок — как в профиле, не как в списке)

java -jar validum.jar generate individual --seed 7 -n 3 --fields short --format csv
# 15 основных колонок: идентификатор, ФИО, пол, дата рождения, возраст, ИНН, СНИЛС,
# паспорт, регион и город прописки, БИК, счёт, документы
```

Опечатка в имени колонки — не тихий пропуск, а отказ:

```powershell
java -jar validum.jar generate individual --fields formName
# Ошибка: Неизвестные колонки: formName. В наборе есть, например: personId, fullName, inn, …
```

То же доступно в REST: `?fields=inn,fullName` или `?fields=short` — но только для CSV-форматов.

## 6. Проверьте себя

Две команды, которые заменяют «поверьте мне на слово».

**`coverage`** — что в наборе есть и насколько оно валидно:

```powershell
java -jar validum.jar coverage --file out/clients.csv
```

```
поле                     заполнено      различных   невалидных
inn                      100% (3/3)     3           0
snils                    100% (3/3)     3           0
…
Валидность значений: проверено 5 полей, невалидных 0 из 15 значений
Согласованность набора: нарушений нет
```

**`describe`** — разбор одной записи человеческим языком:

```powershell
java -jar validum.jar describe --file out/clients.csv --row 1
```

Вы увидите ФИО, возраст, ИНН и СНИЛС с отметкой «валиден», паспорт с датой выдачи и сроком
действия, код подразделения, согласованный с регионом, адреса и счёт с БИК банка.

Если сгенерировать данные с ошибкой (`--corrupt`, шаг 8) — `coverage` покажет ненулевые
«невалидные», а `describe` подчеркнёт проблему. Это и есть проверка, что вы смотрите на реальные
данные, а не на красивую картинку.

## 7. Свой набор из файла

Когда нужно повторять один и тот же набор в CI, удобнее держать его в файле спецификации:

```powershell
$spec = @'
{
  "type": "individual",
  "count": 100,
  "seed": 42,
  "asOf": "2026-01-01",
  "format": "csv-semicolon",
  "ageRange": "18-40",
  "documents": "auto",
  "fields": "short"
}
'@
[IO.File]::WriteAllText("out/set.json", $spec, (New-Object System.Text.UTF8Encoding($false)))

java -jar validum.jar generate --spec out/set.json -o out/set.csv
```

Ключи в файле — те же, что у флагов CLI (`--unique` → `"unique": true` и т.д.); неизвестный ключ
не игнорируется, а даёт ошибку со списком допустимых.

Опечатка в имени ключа ловится сразу:

```powershell
java -jar validum.jar generate --spec out/broken.json
# Ошибка: Неизвестные ключи: sed. Допустимо: type, count, seed, …
```

**Уникальность.** Если нужны неповторяющиеся значения:

```powershell
java -jar validum.jar generate individual --seed 1 -n 1000 --unique --format csv
```

- `--unique` **требует** `--seed` — без него отказывается: иначе набор не воспроизводим.
- Ёмкость конечна: 1 000 000 ИНН не сгенерировать, если у пула меньше вариантов — инструмент
  скажет, сколько всего вариантов, вместо тихих дублей.

## 8. Негативные данные

Тесты должны проверять не только успех. Порча — по одному полю за раз:

```powershell
java -jar validum.jar generate individual --seed 3 -n 5 --corrupt inn,snils -o out/bad.csv --format csv
# в stderr: # испорчено: inn,snils
```

Доступно: `inn`, `snils`, `address` (пустой индекс и строка без улицы). Всё остальное в записи
остаётся валидным — чтобы тест не падал сразу по десяти причинам.

Проверить, что порча доехала до файла:

```powershell
java -jar validum.jar coverage --file out/bad.csv
# inn      100% (5/5)   5   5      ← все пять невалидны
# snils    100% (5/5)   5   5
```

## Если что-то не работает

| Симптом | Причина и лечение |
|---|---|
| `Ошибка: файл не найден — …\data\ED807.xml` | Шаг 2 не выполнен: `fetch-bik -o data/ED807.xml` |
| В PowerShell вместо кириллицы `╨С╨Ш╨Ъ` | Консоль в cp866: `chcp 65001`, затем переменные `[Console]::OutputEncoding = [Text.Encoding]::UTF8` |
| `Ошибка: Неизвестный формат` | Форматы: `json`, `json-array`, `csv`, `csv-semicolon`, `sql` |
| `Ошибка: --unique требует --seed` | Добавьте `--seed` — без него набор невоспроизводим |
| `Хэш двух прогонов не совпал` | Не задан `--as-of`: при повторном прогоне в другой день берётся другая «сегодняшняя» дата |
| `java -jar` ругается на неизвестный флаг | Старый jar: пересоберите `./gradlew :validum-cli:shadowJar` и сверьте `version` |
| REST отвечает `503 bik_source_missing` | На сервере нет справочника: положите `data/ED807.xml` рядом с запуском API |
