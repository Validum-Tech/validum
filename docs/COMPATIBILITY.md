# Совместимость (контракт для тех, кто подключает validum)

Это обещания, на которые можно опираться при подключении `validum-core`, `validum-allure`,
CLI и REST. Всё, чего здесь нет, — не гарантия.

## 1. Java

| Артефакт | Байткод | Что нужно потребителю |
|---|---|---|
| `validum-core` | Java 17 | JDK 17+ |
| `validum-allure` | Java 17 | JDK 17+, JUnit 5 |
| `validum-cli` (fat jar) | Java 17 | JDK 17+ |
| `validum-api` (REST-сервис) | Java 21 | JDK 21 (требование Spring Boot 3.5) |

Собираем на toolchain 21, но для библиотек включён `--release 17`: используем только API,
доступный в 17. Проверяется в CI отдельной полосой на JDK 17 (`-Pvalidum.javaToolchain=17`),
поэтому «работает на 17» — не обещание, а проверенная сборкой вещь.

## 2. Зависимости

`validum-core` не тянет **ничего** в runtime: только JDK. Это принцип, а не случайность —
если появится зависимость, это будет отдельное решение с обоснованием.

`validum-allure` в опубликованном POM **не объявляет** Allure: модуль компилируется против
`allure-java-commons:2.29.1` (`compileOnly`), а версию в проект приносит потребитель:

| Ваш Allure | Что у вас в зависимостях | Совместимо |
|---|---|---|
| 2.29.x | `io.qameta.allure:allure-junit5` | да (это наш «пол») |
| 2.35.x | `io.qameta.allure:allure-jupiter` | да |

Правило: `validum-allure` использует только `io.qameta.allure.Allure` (стабильный фасад, есть в
обеих ветках). `AllureDependencyFloorTest` падает, если код снова начнёт ссылаться на
`allure-junit5`/`specs`/`model` — то есть на API, которого нет в минимальной версии.

Jackson (`jackson-databind`, `jackson-datatype-jsr310`) объявлен в POM `validum-allure` как
обычная зависимость — версия 2.18.2. Если у вас другая 2.x, Maven/Gradle выберет одну; конфликтов
API мы не используем.

## 3. Контракт вывода

**Аддитивность.** Между минорными версиями мы добавляем колонки, поля JSON и DTO, но не удаляем
и не переименовываем существующие. Пример 0.3.0: `personId`, `isResident`, `citizenship` —
новые колонки в начале/середине плоского вывода; старые на месте. Пример 0.4.0:
`passportExpirationDate` («Действителен до») — тоже аддитивно.

**Детерминизм.** Один `seed` (+ `asOf`) → один и тот же набор. Это контракт, закреплённый
golden-фикстурами: SHA-256 каноничного набора для фиксированных `seed + asOf`
(`validum-core/src/test/resources/golden/`). Если отпечаток меняется в минорной версии — это
описано в CHANGELOG отдельной строкой.

**Дата расчёта (`asOf`).** Возраст, даты выдачи документов и проверки считаются от явной даты.
Без `asOf` берётся `LocalDate.now()` — тогда наборы на разные дни будут разными; для
воспроизводимых прогонов задавайте `asOf` явно (CLI `--as-of`, REST `"asOf"`).

**Форматы CSV.**

| Формат | Разделитель | Заголовки | Кодовые поля | Для кого |
|---|---|---|---|---|
| `csv` | `,` | английские | как есть | конвейеры, скрипты, `awk` |
| `csv-semicolon` | `;` | русские | `="…"` (текст для Excel) | человек, Excel |
| `json`, `json-array` | — | — | — | программная обработка |

Машинный `csv` не меняется между версиями. `csv-semicolon` — «дружелюбный» профиль: его
заголовки и обёртки `="…"` могут уточняться (это не контракт для парсеров; парсить надо `csv`).

**Ошибки.** CLI: код 2 — ошибка ввода/конфигурации (сообщение в stderr, префикс «Ошибка:»).
REST: 400 — невалидный ввод, 503 `bik_source_missing` — не найден справочник БИК, 500 —
внутренняя ошибка. Код 2 не означает падение.

## 4. Ломающие изменения

До 1.0 допускаются в минорных версиях, но с двумя условиями: строка в CHANGELOG и обновлённый
этот файл. Планируются в 0.5.0:

- перемещение пакетов `ru.validum.core.export` → `format` / `mapping` / `cbr` (импорты у
  потребителей `validum-core` придётся поправить);
- разбиение `DocumentsCsv` на три класса;
- вынос `Builder` из `IndividualProfileGenerator`.

## 4.1 Что менялось в минорных версиях

| Версия | Тип изменения | Что добавилось |
|---|---|---|
| 0.3.1 | аддитивное | колонка `passportExpirationDate` («Действителен до») в плоской выдаче и `describe`; срок паспорта по рубежам 20/45; исправления `-o` с подкаталогами, `--age-distribution` без диапазона, `--spec` без `ageDistribution`, `--unique-pool` |

Ломающих изменений в 0.3.1 нет: имена и типы существующих полей, сигнатуры и коды ошибок
не менялись. Поля, которые читаются по имени, продолжают работать.

## 5. Известные ограничения

- **Вес.** В jar едут справочники: адреса КЛАДР (12 МБ, 91 файл), ОКВЭД (428 КБ). Это плата за
  офлайн-работу; выделение в отдельный артефакт — после 1.0.
- **Регионы.** 16 субъектов РФ (как в текущем срезе `Region`), а не все 89.
- **Нерезиденты.** 11 стран с синтетическими улицами; реальных адресов зарубежных стран нет.
- **ДУЛ.** 11 видов СПДУЛ; четыре (миграционная карта, свидетельства о рождении/смерти, паспорт
  моряка) сознательно не реализованы — нет акта с разрядностью.

## 6. Как проверить совместимость у себя

```bash
# библиотека на вашем JDK (минимум, без лишнего):
./gradlew -Pvalidum.javaToolchain=17 build

# CLI работает на JDK 17:
java -jar validum.jar version
```
